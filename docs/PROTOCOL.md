# Concurrent ownership and visibility

The owner combines the Herdr socket, original parent pane and native session ID. Every role state, launch and control record binds owner, role, selected scope epoch and a fresh token. Process verification checks executable, complete argv, state path, tab membership and creation identity. A title cannot authorize adoption or cleanup.

Todo reads real custom entries on the selected native branch. Public post-commit notification follows a real committed transaction. Resume, fork, tree and reload rebase the scope; stale publications cannot cover current native data.

Scoped extension events join Todo owner and DAG provider. Source readiness allows layout negotiation. Rendering readiness is separate: native masking needs current matching painted ACKs, including sequence/token, for every required role. A state-file write or PID alone proves no paint. Closure, failure, disconnect or expired lease restores the captured native factory through its original setter when coverage is unavailable.

Follow/folding/scroll preferences belong to one role/scope. Automatic reveal is transient. Completion/removal hands follow to the next eligible target. A same-scope read error retains the target privately and shows unavailable/last-known status; recovery cannot jump to an earlier still-running target.

Reopened roles use verified surviving sibling regions. Swap involves only a new owned pane and its verified sibling, preserving conversation geometry and surviving role identities. Unready/foreign anchors cannot authorize a split. Initial column height is 40/30/30 with terminal rounding.

Metrics distinguish missing, partial, estimated and reported values. Reported zero is retained. Generation speed uses generation milliseconds, never runtime milliseconds. Missing data cannot imply free usage or a billing estimate.
