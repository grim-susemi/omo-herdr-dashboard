# Concurrent ownership and visibility

The owner combines the Herdr socket, original parent pane and native session ID. Every role state, launch and control record binds owner, role, selected scope epoch and a fresh token. Process verification checks executable, complete argv, state path, tab membership and creation identity. A title cannot authorize adoption or cleanup.

Todo reads real custom entries on the selected native branch. Public post-commit notification follows a real committed transaction. Resume, fork, tree and reload rebase the scope; stale publications cannot cover current native data.

Scoped extension events join Todo owner and DAG provider. Source readiness allows layout negotiation. Rendering readiness is separate: native masking needs current matching painted ACKs, including sequence/token, for every required role. A state-file write or PID alone proves no paint. Closure, failure, disconnect or expired lease restores the captured native factory through its original setter when coverage is unavailable.

Follow/folding/scroll preferences belong to one role/scope. Automatic reveal is transient. Completion/removal hands follow to the next eligible target. A same-scope read error retains the target privately and shows unavailable/last-known status; recovery cannot jump to an earlier still-running target.

The integrated owner claims the band layout for new managed dashboards. Todo is a wide band across the top of the dashboard area; ordinary workers sit below it on the left and DAG on the right. An existing `columns` claim stays columns on automatic paths, which leave the conversation's rect and input focus unchanged. It moves to the band only on an explicit `/dashboard`, which keeps the conversation's rect unchanged and ends with focus on the conversation; swaps may briefly select a dashboard pane. Unmanaged mode keeps its current layout. Existing stacked layouts migrate only when all four panes belong to the verified owner, including the conversation. Pane identities and independent view preferences survive movement. Rolling back to install generation 7 after a band claim makes generation 7 read `band` as the legacy stacked layout (NOT VERIFIED); start a new conversation after a rollback. A foreign pane or changed input selection defers migration. `/dashboard` explicitly reopens every role; source updates respect manual closure.

Metrics distinguish missing, partial, estimated and reported values. Reported zero is retained. Generation speed uses generation milliseconds, never runtime milliseconds. Missing data cannot imply free usage or a billing estimate.

## Selected-tab focus qualification

The selected Herdr pane is observed without caller pane environment variables.
Herdr 0.9.3 swap selects the swapped source; owned reopening restores the prior
verified input target through verified neighbors only while that operation still
owns the observed current selection. A later observed manual choice remains
authoritative. Selection checks and separate RPCs are not atomic. An inactive
owner tab defers placement before split; missing DAG-owned roles have no live
coverage. Todo coverage is independent: its own ready ACK may still cover its
native display, and closing or losing Todo readiness restores its original
native factory. Selecting the owner tab and retrying `/dashboard`
recovers the matching roles and ACK-based
masking. Validation checks the final observed input target. Transient selection
can occur; no OS foreground or hardware keyboard guarantee is claimed.

From the source checkout, `npm run qa:live -- --senpi-root <sdk> --dag-root
<companion> --evidence <directory> --scenario focus-reopen` runs this bounded
repair scenario in both registration orders. Omitting `--scenario` retains the
full matrix. QA briefly selects only its created tabs and restores the original
tab only while a fresh observation still selects an owned QA tab; an external
observed manual selection is preserved. The focus-reopen scenario is affected
proof only; historical full-matrix captures remain qualified by unchanged bytes.
